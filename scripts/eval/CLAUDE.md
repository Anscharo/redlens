# Chat evals and bakeoffs

Each `pnpm eval:*` script measures one chat or retrieval decision against labeled data and writes its results to `.cache/eval-*.json`. The lanes these bakeoffs tune are described in `src/server/facts/CLAUDE.md`; the full harness is in `docs/chat-system.md` §12.

```bash
pnpm eval:*         # every `scripts/eval/` entry point below is auto-attributed to "Sky Atlas Redline Evals" on OpenRouter; an eval script placed elsewhere needs OPENROUTER_APP_KIND=eval (see Conventions)
pnpm eval:retrieval # grouping / embed-model / reranker bakeoff → .cache/eval-retrieval.json (tfidf without a key; --backend openrouter for neural)
pnpm eval:facts     # fact-trigger bakeoff: regex vs on-device similarity vs the hybrid, over 241 labeled questions (hand-written + generated from real atlas titles) → .cache/eval-facts.json. Add --embed for the similarity arms; set DATABASE_URL to also score real user messages. Fits its threshold on half the set and reports on the other half.
pnpm eval:census    # census-routing bakeoff (sibling to eval:facts — different shape, 1-of-10 routing not fire/no-fire): regex vs on-device similarity (rankPrototypeSets) vs the hybrid, over 202 labeled questions (each carrying an expected census slug) → .cache/eval-census.json. Set DATABASE_URL to also false-fire-check real user messages — decisive last time: it's what set the shipped margin, a labeled-corpus-only threshold would have shipped a lane that mis-fired on ~1 in 5 real chat turns. Fits its threshold on half the set and reports on the other half.
pnpm eval:complexity # tier-router similarity-lane bakeoff (third consumer of the same embedding): should a whole-corpus question reach the STRONG model tier by regex alone, or also by similarity? 180 labeled questions (28 hand-written positives phrased to avoid every regex trigger + 144 generated single-subject negatives) → .cache/eval-complexity.json. The regexes score 0/28 on natural paraphrases — their bakeoff score is in-sample. Set DATABASE_URL to also false-fire-check real messages; that check has NOT been run for this lane's shipped margin.
pnpm eval:announce   # promised-tool lane bakeoff (FOURTH consumer of the same embedding, and the first to score an ANSWER rather than a question): should chat-loop.ts retry a round that announced a lookup — "one moment while I search the atlas" — and called no tool? 144 labeled cases (28 announcements, 12 of them phrased around every regex, + 116 answers including 80 generated from real atlas subjects and 7 pinned regex-hole sentences from the 2026-09-02 review) → .cache/eval-announce.json. Regex alone 57% recall; the hybrid 75%, both at ZERO false fires over 116 answers — and on real traffic 17 of 18 tool-free assistant answers never get past the deterministic envelope at all. Set DATABASE_URL to also check real tool-free assistant answers (a dev DB was all that was available; re-run against production before lowering the margin).
```
