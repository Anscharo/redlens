## 1. Executive vote vs governance poll (from the portal code + the repo templates)

| | **Executive vote** | **Governance poll** |
|---|---|---|
| Object voted on | An on-chain **spell contract** (`address:` in the doc frontmatter; `parseExecutive.ts` rejects docs whose `address` fails `getAddress()`), i.e. binding protocol changes | An off-chain **signal**: a markdown file whose IPFS multihash is registered on the polling contract (`PollCreated(creator, blockCreated, pollId, startDate, endDate, multiHash, url)` — `gpv2/modules/contracts/generated.ts` ~L3133) |
| Who votes | MKR (now SKY) locked in **DSChief**: `chief.approvals(spell)` is the support figure (`gpv2/modules/executive/api/analyzeSpell.ts`; `getChiefApprovals.ts`); `lock/free/vote/lift/hat` ABI in `generated.ts` L152-L366. Sky-era support field is `spellData.skySupport` (`types/skyExecutive.ts`) | Same chief-locked weight, snapshotted at poll end: spock query `voteAddressMkrWeightsAtTime(argPollId, argUnix)` (`gpv2/modules/gql/queries/spock/voteAddressMkrWeightsAtTime.ts`, used by `modules/polling/api/fetchVotesByAddress.ts`). Votes are `vote(pollId, optionId)` / batched `vote(pollIds[], optionIds[])` on the polling contract (mainnet `0xD3A9FE26…`, Arbitrum gasless `0x4f4e551b…`, `generated.ts` L3243/L3460) |
| Outcome rule | **Continuous approval**: the spell with most approvals is `lift`ed to the **hat** (`useHat.ts`, `useMkrOnHat.ts` read `chief.hat()`); status text "`N additional SKY support needed to pass`" = `skyOnHat − skySupport` (`gpv2/modules/executive/helpers/getStatusText.ts` `getSkyStatusText`). Once hat, `spell.schedule()` plots it on the pause, later `spell.cast()` | **Victory conditions** evaluated off-chain over the vote list, if/else in array order, with `and` groups agreeing (`gpv2/modules/polling/api/fetchPollTally.ts`); implementations in `api/victory_conditions/{plurality,majority,instantRunoff,approval,comparison,default}.ts`; spec `gpv2/docs/POLL_PARAMETERS.md`. Abstain ballots are excluded from `totalMkrActiveParticipation` but counted in `totalMkrParticipation` |
| Timing | Bi-weekly Thursdays (29/30 exec-votes docs are Thursdays; 23/29 gaps = 14 d). **GSM Pause Delay** (`pause.delay()`; doc says "currently set to 48 hours", linking Atlas `db442d8a…` = A.1.10.3.1.2 *Pause Delay Current Value*); optional **office hours** modifier (`spell.officeHours()`, "14:00–21:00 UTC Mon–Fri"); **30-day expiry** (`spell.expiration()`, template: "If this executive proposal does not pass within 30 days, then it will expire") — all in `exec-votes/templates/executive-vote-template.md` | Weekly cycle: 143/144 sky-polls start **Mon 16:00 UTC**, 142/144 last **3 days** (community era: 1190/1215 Monday starts; 762 × 3 d, 351 × 14 d for MIP/monthly ratification polls). Atlas Edit **Weekly** (tag `weekly`, 65 polls) vs **Monthly** (AEP, tag `monthly`, 1 poll) templates in `sky-polls/templates/Atlas/` |
| Identifiers | spell `address` (checksummed); `key` = `slugify(title)` (`parseExecutive.ts`), URL `vote.sky.money/executive/<key>`; the detail API accepts `0x…` or kebab key (`fetchSkyExecutiveDetail.ts` regex). `executiveHash` = the `0x…` inside `spell.description()` (hash of the doc) | `pollId` (uint, on-chain), `multiHash` (IPFS CID of the doc), `slug = multiHash.slice(0,8)` (`gpv2/modules/polling/helpers/parsePollMetadata.ts` `spockPollToPartialPoll`), URL `vote.sky.money/polling/<slug>`; `url` = raw GitHub markdown |
| Status fields | `spellData`: `hasBeenCast` (`done()`), `hasBeenScheduled` (`!!eta`), `eta`, `expiration`, `nextCastTime`, `datePassed` (block time of the pause `plot` event for the spell — `getSpellScheduledDate.ts`), `dateExecuted` (`getSpellExecuationDate.ts`), `mkrSupport`/`skySupport`, `executiveHash`, `officeHours`; `active` = listed in `active/proposals.json` (`parseExecutive.ts`; `EXEC_PROPOSAL_INDEX` in `executive.constants.ts`) | `active` ⇔ `startDate <= now < endDate` (`fetchPolls.ts` `getActivePollIds`, `PollStatusEnum {ACTIVE, ENDED}`); the tally carries `winner`, `winningOptionName`, `victoryConditionMatched` (index into the conditions array), `numVoters`, per-option `firstPct/transferPct/eliminated` for IRV |
| Lifecycle link | Poll passes → its item is bundled into the next executive doc as an `**Authorization**: [Governance poll NNNN](https://vote.sky.money/polling/<slug>)` bullet (57/188 sections) or a `[Sky Atlas](https://sky-atlas.io/#<uuid>)` authority (94/188) → spell lifted → `schedule()` → GSM delay → `cast()` (`executive-doc-review-checklist.md`, `review-executive-doc/SKILL.md` §"Authorization / Proposal links") | |

Old vs new era markers: doc H1 names **MKR** Holders (community) → **SKY** holders (exec-votes); `spellData.mkrSupport` → `skySupport` (`gpv2/modules/executive/types/spellData.d.ts` `SpellData` vs `SkySpellData`); the frontmatter `title:` deliberately keeps the `Template - [Executive Vote] ` prefix, which `parseExecutive.editTitle` strips.

## 2. Sky API JSON shapes (reconstructed from gpv2 — what we would ingest)

Proxied endpoints (all under `https://vote.sky.money/api/`): `polling/all-polls-with-tally?pageSize&page`, `polling/<pollIdOrSlug>?network=`, `polling/tally/<pollId>?network=`, `executive?start&limit`, `executive/<keyOrAddress>`, `executive/supporters`, `executive/hat?network=`. Sources: `gpv2/pages/api/sky/polls.ts`, `polls/[pollIdOrSlug].ts`, `polls/tally/[pollId].ts`, `executives.ts`, `executives/[proposalIdOrKey].ts`, `executives/supporters.ts`, `hat.ts`, `modules/executive/api/fetchSkyExecutiveDetail.ts`, `modules/executive/types/skyExecutive.ts`.

```ts
// GET /api/polling/all-polls-with-tally      (SkyPollsResponse, pages/api/sky/polls.ts)
{ paginationInfo: { totalCount, page, numPages, hasNextPage },
  stats: { active, finished, total, type: { [inputFormat]: number } },
  polls: [{ pollId: number, startDate: ISO, endDate: ISO, multiHash, slug, url, discussionLink, type,
            parameters: { inputFormat: { type, abstain: number[], options: any[] }, victoryConditions: any[], resultDisplay },
            title, summary, options: any[] /* detail: {[optionId]: name} */, tags: string[],
            tally?: { parameters: { victoryConditions }, results: [{ optionId, skySupport: string, firstPct }],
                      totalSkyParticipation: string, totalSkyActiveParticipation: string, winner: number|null,
                      winningOptionName: string|null, numVoters, voteBreakdown: any[], victoryConditionMatched?: number } }],
  tags: [{ id, shortname, longname, description, precedence, count? }] }
// GET /api/polling/<pollIdOrSlug>           (SkyPollDetailResponse) = poll item + content: string (HTML) +
//   options: {[id]: string} + tags: Tag[] + tally with results[{optionId, winner, skySupport, optionName, transfer,
//   firstPct, transferPct}], votesByAddress[{skySupport, ballot: number[], pollId, voter, chainId, blockTimestamp, hash}]
//   + ctx: { prev: {slug}|null, next: {slug}|null }
// GET /api/polling/tally/<pollId>           (SkyPollTallyResponse) = that tally object alone
// GET /api/executive                         (SkyExecutiveListItem[])
[{ title, proposalBlurb, key, address, date: string, active: boolean, proposalLink,
   spellData: { hasBeenCast?, hasBeenScheduled, nextCastTime?, datePassed?, dateExecuted?, skySupport: string,
                executiveHash?, officeHours?: boolean /* arrives as "true"/"false" string; proxy coerces */ } }]
// GET /api/executive/<key|0x..>             (SkyExecutiveDetailResponse) = list item + content: string (HTML)
//   + supporters?: [{ address, skySupport: string, percentage: number }] + ctx?: { prev:{key}|null, next:{key}|null }
// GET /api/executive/supporters              { [spellAddress]: [{ address, deposits: string, percent: string }] }
// GET /api/executive/hat                     { hatAddress, skyOnHat: string /* wei */, network }
```
Notes: the list endpoints truncate `content` to 100 chars (`fetchExecutives.ts`, `fetchPolls.ts` `_getAllPolls`); `victoryConditions` items follow `PollVictoryCondition*` in `gpv2/modules/polling/types/poll.d.ts` (`{type:'and',conditions[]}`, `{type:'comparison',comparator,value,options}`, `{type:'default',value}`, `{type:'majority',percent}`, `{type:'plurality'|'approval'|'instant-runoff'}`); `PollInputFormat` = `single-choice|rank-free|choose-free|majority` (`polling.constants.ts`). The exec-votes review skill confirms the poll detail `url` field points at the source markdown (`exec-votes/.claude/skills/review-executive-doc/SKILL.md` L151-159).

## 5. Where post-May-2025 data lives, and what is reachable with GitHub/git only

- gpv2 HEAD (the MKR portal) still reads **makerdao/community** for polls (`POLLS_HASH_FILE_URL`, `AGGREGATED_POLLS_FILE_URL` in `modules/polling/polling.constants.ts`; `hashed-polls.json` is the cache-invalidation hash) and **sky-ecosystem/community** `governance/votes` via the GitHub GraphQL tree query for executives (`modules/executive/api/fetchExecutives.ts`, `EXEC_PROPOSAL_INDEX` = `…/sky-ecosystem/community/master/governance/votes/active/proposals.json`). Both stop in May 2025 (last poll 1254 on 2025-05-12, last exec 2025-05-15) — this is the archive.
- The Sky portal's own data comes through `https://vote.sky.money/api/*` (proxied in `pages/api/sky/**`) and, for votes, the **spock** GraphQL at `https://gov-polling.sky.money/api/v1` (`modules/gql/gql.constants.ts`: `activePolls`, `voteAddressMkrWeightsAtTime`, `allCurrentVotes`, `lastPollVote`) plus an Envio HyperIndex subgraph at `${NEXT_PUBLIC_PROXY_ORIGIN}/indexer` (delegates only). gpv2 has no code for the current poll/exec repos — its own README still names `sky-ecosystem/community`.
- The live corpora are **sky-ecosystem/executive-votes** (`active/proposals.json` → `2026/executive-vote-2026-09-10-…md`; `index.json` `[{path, metadata:{title,summary,date,address}}]` regenerated by `scripts/generate-exec-index.ts` / `.github/workflows/update-index.yml`) and **sky-ecosystem/polls** (`index.json` + `meta/tags.json` + `meta/poll-tags.json` keyed by pollId). Both are cloned; per coordinator, no further repo discovery was attempted.
- **Ingestible with git alone**: every poll/exec markdown + frontmatter (title, summary, date, address, discussion_link, parameters, options, start/end), the active spell address, the tag catalogue, tags per pollId, 95 pollId↔slug pairs from exec Authorization bullets, and all atlas links above. **Needs vote.sky.money (or chain)**: pollId/multiHash/slug for each poll file, tallies/winners/`victoryConditionMatched`, votesByAddress, `spellData` (cast/scheduled/passed/executed dates, skySupport), supporters, hat. `sky-atlas.io/api/atlas.md|.json` also exists as a flat export (`review-executive-doc/SKILL.md` L178-190) — not needed given the submodule.

## 6. On-chain recovery (feasibility only)

Contracts the portal reads (`gpv2/modules/contracts/generated.ts`): polling `0xD3A9FE267852281a1e6307a1C37CDfD76d39b133` (mainnet; `PollCreated`/`PollWithdrawn`/`Voted` events, `createPoll(startDate,endDate,multiHash,url)`, `npoll()`) and `0x4f4e551b4920a5417F8d4e7f8f099660dAdadcEC` (Arbitrum gasless `Voted`), old polling `0xF9be8F09…`; DSChief `0x0a3f6849f78076aefaDf113F5BED87720274dDC0` (`approvals(spell)`, `hat()`, `lift`, `lock/free/vote`; old chief `0x9eF05f7F…`); DSPause `0xbE286431454714F511008713973d3B053A2d38f3` (`delay()`, `plans`, the `plot` event whose block time is `datePassed`) and pause proxy `0xBE8E3e36…`; each spell exposes `done/eta/expiration/nextCastTime/officeHours/description`. Caveat: gpv2 HEAD only carries the MKR-era chief; the SKY chief address is not in the repo (the portal fetches `hatAddress` from `vote.sky.money/api/executive/hat`). With `scripts/required/snap-chainstate.mjs`'s viem multicall pattern we could: (a) replay `PollCreated` logs on the polling contract to map pollId→multiHash→slug→`url` (the raw GitHub path, i.e. the file), the missing join for sky-polls; (b) multicall `done/eta/expiration/nextCastTime/officeHours` + `chief.approvals` for every `address:` in exec docs to rebuild `spellData` without the API; (c) read `pause.delay()` for the live GSM value. Only an RPC endpoint is involved; no portal access.
